## About this book

This book is a set of epub-test-books, a library of small EPUB files that each show one rule or one defect.

A small generated JPEG shown in the content document is declared in the manifest as image/jpg instead of image/jpeg. Everything else is the EPUB 3 template, which raises no finding.

Expected result: Invalid. The table in [`sec-core-media-types`](https://www.w3.org/TR/epub-33/#sec-core-media-types) designates `image/jpeg` for JPEG. A tool may instead treat the image as a foreign resource with no fallback. That follows from the same defect.

## Question

A generated JPEG shown in a content document is declared in the manifest as `image/jpg` instead of `image/jpeg`. Does a validator reject it?

## Clause

EPUB 3.3, [`sec-item-elem`](https://www.w3.org/TR/epub-33/#sec-item-elem):

> For core media type resources, EPUB creators MUST use the media type designated in 3.2 Core media types.

## Expected result

Invalid. The table in [`sec-core-media-types`](https://www.w3.org/TR/epub-33/#sec-core-media-types) designates `image/jpeg` for JPEG. A tool may instead treat the image as a foreign resource with no fallback. That follows from the same defect.

## Verifier results

| Verifier | Command | Result | Output |
|----------|---------|--------|--------|
| epubveri 0.41.0 | `epubveri -i media-type-image-jpg.epub -u --advisory` | ERROR RSC-032; INVALID | `media-type-image-jpg.epubveri-0.41.0.txt` |
| epubcheck 5.4.0 | `epubcheck media-type-image-jpg.epub -u` | ERROR RSC-032; INVALID | `media-type-image-jpg.epubcheck-5.4.0.txt` |

Both agree with the expected result, so there is nothing to mark. They report the same messages.

Both treat the image as a foreign resource with no fallback, as the expected result allowed for. With `image/jpeg` in place of `image/jpg`, the same book gets no finding from either tool.

Every epubveri finding here is in its default output. None is an `--advisory` finding.

## Build

`OEBPS/image.jpg`, generated by `scripts/lib/minijpeg.py`, is added to the manifest as `image/jpg` and shown in `content.xhtml`. The accessibility metadata says the book has an image.
